# Shared Sovereign Engine

New combined live conversations and paired MCP calls use `/api/engine` and the same Supabase state machine. Legacy conversations retain their original resumable workflow. Selecting or explicitly requesting one model uses that reporter followed by the chosen Boss editor. Other requests receive task-specific complementary assignments from the configured registry of six providers and five Hugging Face routes.

## What is implemented

- Registry: route, credential presence, model family, supported text/search operations and role priors. Credentials never enter prompts. HF native audio/video/image generation is not enabled by a text inference route.
- Allocation: the planner chooses useful, distinct assignments within the run budget. Contributors provide work and task-fit objections. Boss reconciles those objections and task ownership in the candidate. Recent successful/failed responses and latency for the same task class inform allocation after at least three observations. These observations do **not** measure intelligence or correctness.
- Evidence: the original request, project context, selected attachment briefs, enabled connector snapshot and explicitly saved project memory are shared. Citations and actual reported model identity survive into review. One focused Perplexity evidence follow-up is allowed when a reviewer identifies a factual gap. Source snippets are bounded; originals remain in the saved run.
- Review: Astra and Fable independently receive the same SHA-256-bound candidate. Reviews are parsed and validated; wrong hashes, blocking ACCEPT decisions, model-family mismatches and failures cannot count as acceptance. At most one correction and two review rounds. The exact accepted candidate is returned with server-generated review metadata. Continued disagreement returns the best saved candidate with blockers rather than looping or leaving a blank result.
- Durability: Supabase stores each call reservation before inference, then its output, usage and receipt. Atomic claims, leases, owner-scoped reads and stale-writer checks protect concurrent workers. Closing the browser stops polling, not the server job. The existing Railway dispatcher advances queued work, normally one stage each cron tick. While the dashboard is open, bounded `after()` work accelerates progress.
- Recovery: a lease older than six minutes becomes paused. Explicit resume skips a possibly charged pending call; it does not replay it. Completed stages remain intact. Cancellation cannot undo a request already sent to a provider.
- Cost controls: default 14 calls per cooperative run (UI Full uses 24), two for a requested reporter; input-character budgets; per-stage output caps; a global 64 reserved engine calls per UTC day; two concurrent stages. No automatic HTTP retries for engine inference. Upstream search/tool usage can also be billed. These controls are **not a dollar cap** because route prices are not uniformly supplied. Attachment preprocessing and legacy workflows have their separate controls.
- Actions: exact immutable payload/hash, fifteen-minute approval, atomic at-most-once dispatch and receipt. Available choices are private outcome artifact, explicitly saved shared project memory, and a Gmail handoff asking Aya to review the draft only. The last returns `submitted` with message/thread IDs, never a claim that Aya completed the task. Account execution, builds and publishing retain their existing explicit flows. No arbitrary code execution or cloud-build setting is enabled by this engine.
- Recovery UI: **Saved engine runs** opens prior dashboard or MCP runs after a reload or on another authenticated device. Process details expose route provenance, assignments, reviews and action previews without displaying secret values.

## Deployment and security

Apply `supabase/migrations/202610200001_unified_engine.sql`. New tables have RLS enabled and no anon/authenticated grants. Only server-side service-role code accesses them. Browser mutations require owner authentication and same-origin checks; the MCP gateway retains its bearer credential. `/api/config` enables the new path only when the database table is available. Production uses the existing Railway dispatcher; no new service or account is required.

The legacy MCP local-only workflow remains available for installations without a paired remote gateway. A paired `synthesize_request` returns a durable run ID promptly; read its result with `sovereign_engine_read`. Additional tools: `sovereign_engine_launch`, `sovereign_engine_list`, `sovereign_engine_resume`, `sovereign_engine_cancel`. A queued submission is not a finished deliverable.

## Quality evaluation

No benchmark superiority or provider-wide live capability is claimed. Tests use deterministic provider fixtures; the live database smoke check performs zero inference calls. Key presence does not establish credit or access.

For a paid comparison, freeze 30 representative tasks (10 coding, 10 source-grounded research, 10 creative/structured production), acceptance rubrics and input packets first. Run each through standalone Astra, standalone Fable and this engine with the same tools and maximum dollar/latency allowance. Score artifacts blind to model identity: requirement completion, objective test results, factual support and unsupported claims. Count failures, all retries, search charges, token usage and total latency. Do not discard failed runs or award a consensus bonus. Use `scripts/compare-engine-benchmarks.mjs results.json` for a paired summary of recorded results. The script makes no network calls and does not generate synthetic scores.

Required input rows: `{taskId, condition: "astra"|"fable"|"engine", quality: 0..100, completed: boolean, unsupportedClaims: nonnegative integer, latencyMs: nonnegative number, costUsd: nonnegative number}`. Record actual provider costs; do not estimate missing costs as zero. Only complete three-condition task sets are compared. Fewer than 30 complete tasks is explicitly labelled preliminary.
